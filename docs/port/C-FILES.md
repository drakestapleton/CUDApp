## What #280 means for the port

#280 changes 118 of the 204 files: 82 of the 83 `src/` files (all but `src/omega_ampere_qmd.c`) and all of `m16/`
and `nvrm/`. For 70 of the 118
its version calls generated Omega units that the main version does not call (column "#280 new unit refs"). Among
them, #280 already carries seeded Omega replacements for the three first-choice leaves of this card:
`src/sha256.c` (`om/core/sha256.om`, unit `core_sha`), `src/omega_gpu_hostmath.c` (`om/core/hostmath.om`, unit
`core_hostmath`) and `src/omega_fp8_slot_table.c` (`om/api/apish_slot.om` + `om/apirest/slot.om`, unit `ar_slot`).
DRA-478 is blocked by DRA-154 for the families #280 changes, which is every `src/` family. A port on main of any
`src/` file would conflict with #280 in the file itself, in `om/units.sh` and in `src/cudapp_native.h`.

Only two hand-written files outside `tests/` are untouched by #280:

- `src/omega_ampere_qmd.c` (19 lines): already a C ABI shim over the seeded `om/encoder/amp_runtime.om`
  (`omega_amp_runtime`). Its product callers (`src/omega_gpu_session.c`, `src/omega_gpu_platform_linux.c`,
  `nvrm/nvrm.c`) are all touched by #280, so removing the shim means editing #280 files.
- `tools/multitarget/spirv-host.c` (315 lines): the OpenCL CPU launcher for the SPIR-V backend. It calls a shared
  library (PoCL), which seeded Omega cannot do yet (checked shared-library calls, omega-mv#888, E2).

Other in-flight or existing Omega work named for this port:

- sm_121 encoder: `om/encoder/bw_enc_sm121.om` is the default (`CUDAPP_ENCODER=om`); the C encoder in
  `src/omega_blackwell_codegen.c` stays as the differential oracle (`CUDAPP_ENCODER=c|diff`).
- cubin writer: `om/cubin/cubin_elf.om` (`omega_cubin_elf`) is called from `src/omega_cubin.c`.
- Ampere: `om/encoder/ampere_enc_sm86.om` and `amp_runtime.om` behind `src/omega_ampere_codegen.c` and
  `src/omega_ampere_qmd.c`.
- NVML (#365): `compat/nvml/` is not on main; on its patch branch `libnvidia-ml.c` is bridge cabi-1 output of
  `native/nvml/api.om`, so it is generated, not hand-written.
- `src/omega_bw_hazard.c`: C only; it is a copy of omega `f0d1e9f5` pinned by a row in
  `tools/extract/drift-baseline.tsv`. No `.om` exists on main or #280.

## Parity of the #280 ports against the f1b50cbf C (card t_b810aa67)

HOST_TESTED on the Spark (AArch64, gcc 13.3.0), no GPU. The harnesses are ORACLE C, kept with the card evidence,
not in this repository. Old C = the f1b50cbf file, renamed and linked into the same binary. #280's own tests that
touch the three files also pass on the fix branch: `om/units.sh --check`, `make test-core-util test-core-algorithms
test-core-mutants` (6 SHA mutants killed), `make test-gpu-fp8-slots` (27/27), `make test-gpu-decode-attn`
(43/43 and maxpos 5/5), `make test-api-shells-diff test-api-shells-mutants` (8 killed), `tests/api_rest_mutants.py`
(7 killed). The slot suites ran at `88a9ea13`; the sha and hostmath suites ran at its first revision `f91e752e`,
which differs only in one line of `om/api/apish_slot.om` (also masking `pins`).

Findings:

1. `ar_slot` divergence (fixed). C keeps `pins` and `pinned_now` in `uint32_t`, so a pin at `pinned_now = 0xffffffff`
   wraps it to 0 and leaves `pinned_high` alone. `om/api/apish_slot.om` adds in 64 bits and compares before the
   unit masks the word back to 32 bits, so `pinned_high` became 2^32, stored as 0. Unreachable in practice
   (2^32 simultaneous pins), but the old and new state machines disagree. Fix: mask the `pinned_now` increment in
   `pin` to 32 bits (`pins` is already wrapped by `om/apirest/slot.om`'s packing mask). Patch on #280: branch
   `hive/t_b810aa67-slot-wrap` at `88a9ea13` (see the READY file), with a regression check in
   `tests/gpu_fp8_slots_test.c` that fails on the d4daaa35 unit.
2. hostmath and FP contraction. The library is built with `-std=gnu11 -O2`, so GCC on AArch64 fuses 9
   multiply-adds in `src/omega_gpu_hostmath.c` (`objdump` count), while an x86-64 default build fuses none: the
   old C gives different bits on the two hosts. The Omega unit computes every operation unfused and matches the C
   built with `-ffp-contract=off`. Against the shipped AArch64 build it differs in 10935 of the in-contract
   comparisons (sincos limited to its documented |a| < 1.6e6), by at most 1.14e-13 relative (pow with a large
   exponent). Outside that contract both are meaningless (cos(2.6e18) differs by 25 orders of magnitude).
3. NaN payloads. 40 comparisons, all pow with a NaN exponent and a base outside log's domain, so both factors of
   `e * log(b)` are NaN: the C returns log's default NaN, the unit returns the exponent's NaN. C does not fix the
   operand order of a commutative multiply, so the C bits are a compiler choice; the unit follows the AArch64
   rule (first operand). These are counted, not gated: every non-NaN result is gated bit for bit.
4. A one-ulp change of LN2_LO was not detected by the hostmath sample: the term moves results by far less than
   one ulp. The gated mutant is the semantic one in the table.
