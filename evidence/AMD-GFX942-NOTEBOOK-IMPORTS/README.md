# Notebook deferred-import repair

The parent found that all three compact sections called math.isfinite without importing math. The earlier export gate did execute the source in a fresh empty namespace, but only invoked the fixture factory; it never exercised the deferred interval-check function. Removing the import had therefore escaped that gate.

The runtime now imports math. Export executes each complete source with exec(source, {}) exactly as the loader does, then checks all generated function code, including nested/decorated functions, for unresolved LOAD_GLOBAL lookups in that same namespace or builtins. Each section has a genuine control deleting its math import, which the new check catches in the interval-check function. This is a host namespace check, not a claim of executing GPU notebook callbacks.

The first scanner attempt incorrectly applied the generated namespace to an imported functools function; that failed log is preserved. The repair follows each function own globals identity and only scans code defined by this section, plus its nested code. The accepted run then passes all three existing numerical suites and source/factory parity checks, with all kernel controls, missing-math controls and missing-case controls CAUGHT. Generated byte counts are in sizes.txt.

Only the notebook runtime/generator and new evidence change. Old code objects and historical receipts are unchanged. The corrected sections are exported to the requested notebook sections directory; actual notebook/GPU execution remains NOT_RUN.
