# C6-DISASM-OM: Omega's own sm_121 disassembler in seeded Omega (CUDA++ C6, DRA-475, kanban t_81083ab1)

Host evidence, Spark (GB10 host CPU, cores 10-11 under pool-10-11). No GPU was opened. GB10 device run: NOT_RUN by
design. nvdisasm 13.0.85 (`/usr/local/cuda/bin/nvdisasm`, sha256
`bc40070d596fa49b81c0905ca1d05e457aaec071280f742997d4a0b511781b25`) is an offline ORACLE only.

## What changed

- `om/disasm/sm121_dis.om`: the decoder, seeded Omega (omc e5b32567, sha256 `2c824805...`). Same rules as the C
  decoder: the 61 rows of the C `ROWS` table (opcode, fixed bits, format string packed 8 ASCII bytes per ulong), the
  same match rule (every bit outside the format's fields and the guard must equal the row), the IMAD-immediate names,
  the special-register, compare and size names. The row table was generated by Wolfram from the C table
  (`wolfram-rows.wl`); the transcription was checked by the SHA-256 Wolfram printed of its own output
  (`f1578d7a5a10c285a276037eae31ad3a029faa1ee3a6556124e31d7892484787`, equal to `head -n 514` of the row block).
- `om/units.sh` lowers it with the pinned omega-bridge (bc11b30b; toc.om / bridge-seeded pins unchanged) into
  `src/cudapp_om_sm121_dis.c` + `.ident`; `src/cudapp_native.h` declares `omega_sm121_dis`.
- `src/omega_sm121_disasm.c`: the public calls (`omega_sm121_disasm`, `omega_sm121_listing`,
  `omega_sm121_padding_start`) keep their signatures and call sites. Default build: the Omega decoder; the file only
  moves bytes and copies text. The hand-written C decoder is compiled only with `CUDAPP_MIGRATION_PENDING_C_DISASM`
  (`make CUDAPP_DISASM=c`) or in the `diff` build, as the differential oracle, the same pattern as
  `CUDAPP_MIGRATION_PENDING_C_ENCODER`.
- Defect found and fixed in both decoders: S2R of special register 82 printed `SR82`; nvdisasm prints
  `SR_GLOBALTIMERLO` (the device-trace emitter uses it). 82/83 are now named, and the 96 other special registers
  nvdisasm names but our table does not are reported as `??` instead of guessed (`sr-sweep.sh`: all 256 values).
- `tools/sm121dis/corpus.sh` writes `MANIFEST.tsv` and `PRODUCERS.tsv`; `check.sh` reports identical/differing kernels
  and the instruction class of every differing word; new `negctl.sh` (flipped-bit control) and `om_mutants.sh`.
- Readers moved off nvdisasm: `tests/device-trace/run-emitter-checks.sh`, `tools/artifact_smoke.sh`
  (`NVDISASM-CALL-SITES.md` lists every call site in CUDApp and omega-mv with its class).
- ZERO-NVDISASM static check, red at base f1b50cbf (15 lines), passes with `tools/sm121dis/oracle-allow.tsv`.

## Normalisation rules (minimal)

`oracle_pairs.sh` takes nvdisasm `-b SM121 -hex`: per instruction the address, low and high 64-bit words and the text
up to and including `;`. Both sides then have every run of white space collapsed to one space. Nothing else: the space
before `;` (nvdisasm omits it after the last EXIT) is reproduced by our listing, not normalised away.
