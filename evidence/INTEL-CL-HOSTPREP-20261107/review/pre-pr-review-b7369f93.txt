Blocking findings

1. P1: ICD pinning accepts paths that ocl-icd interprets as indirection, not libraries.

tools/multitarget/spirv-host.c:335-349 checks absolute spelling, realpath and forbidden substrings, but not file type or the loader’s interpretation. Ocl-icd interprets a directory as an ICD search directory and a filename ending in .icd as a descriptor containing another library name. Only its other path form means direct library loading. ([github.com](https://github.com/OCL-dev/ocl-icd/blob/master/doc/libOpenCL.7.txt.in?utm_source=openai))

[INFERENCE] With MT_CL_GPU=1, a clean-named directory containing NVIDIA’s descriptor, or a clean-named .icd file naming NVIDIA’s library, passes these checks. clGetPlatformIDs at line 442 can then load that driver before platform-count or vendor rejection. The required-mapping check at lines 527-529 is too late to prevent loading and is bypassed entirely by earlier failure returns.

The shell wrapper rejects directories, but its regular-file check still accepts .icd descriptors (tools/access/intel-cl.sh:80-89). The directly built launcher accepts both cases.

Ask: reject directory and descriptor interpretations in the launcher before calling OpenCL. At minimum, require a regular resolved file and reject a resolved .icd suffix. Keep the original/resolved forbid checks. Add negative controls for a clean-named descriptor and directory using a harmless mock driver, proving neither reaches driver initialization.

This is an opted-in isolation defect, not a bypass of the main no-opt-in check.

2. P2: Bundle paths are split and glob-expanded when constructing launcher arguments.

tools/access/intel-cl.sh:46-52 serializes filenames into whitespace-separated text. Lines 111 and 173 reconstruct arguments with unquoted command substitution.

[INFERENCE] ACCESS_BUNDLE=/work/intel bundle produces separate arguments for the path components. For vadd this changes argc and causes refusal instead of running the row. Glob characters in the directory name can also expand. Quoting the plan’s script path does not protect these inner expansions.

Ask: construct positional arguments directly with a kernel case and quoted filenames, without serializing them through stdout. Use the same construction for the flag control. Add a shell argument-capture test with spaces and glob characters in ACCESS_BUNDLE; no GPU is needed.
