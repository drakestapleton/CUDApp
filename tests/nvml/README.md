# NVML host gate

`make test-nvml CUDAPP_OMC_HOST=1 OMEGA_OMC=/absolute/pinned/omc OMEGA_BRIDGE=/absolute/bridge` bootstraps `tests/components/proc.om`, `gate.om` and `mutants.om`. All new test/gate logic is seeded Omega. Run from the repository root, CPU-only, in a device-isolated sandbox. The compiler SHA256 is `2c82480596bbdc50cda9626866209ef662d5834f278f839ff4ce0250c495029f`; the bridge frontend digest is read from `om/units.sh`.

`host.om` ports the 476 checks and shell-call model to Omega. It uses `rmfake.om`, not a real RM or production shared library. `gate.om` compares committed generated bindings, checks their prototypes, builds/runs the model, alters the error-string oracle as a negative control, compares the legacy C caller, checks CUDA-header ABI facts/prototypes, checks the thin-shell guard and its negative control, and executes all 22 mutants. Mutation compilation and exec failure never count as a caught behavioral mutant. The same last-line failure/check counts are retained.

`nvml_test.c`, `transport.c`, `transport.h` and `abi.c` are retained **ORACLE** inputs for the foreign ABI comparison. They are not shipped by this target and no new C logic was added. The handwritten production shell/header in `compat/nvml` are **MIGRATION**, not generated code. Their Omega model successor is `host.om`; the production successor requires `native/nvml/api.om` and the library emitter specified in [omega-bridge#83](https://github.com/aien-dev/omega-bridge/issues/83). Passing the model or thin-shell guard does not remove this HOLD.

The new gate replaces `run.sh`. Direct gate exits preserve 77 for missing compiler/bridge configuration, 69 for pin mismatch, 74 for missing/invalid frontend pin, 1 for rejected behavior, and 0 for success. Make without configuration still exits 2. Failure diagnostics are fail-fast rather than the old shell's accumulated failure count. Healthy summary lines and each mutant's failure/check counts are preserved; the additional `PASS seeded Omega fake tier` identifies the new model. A trap in the model exits with its trap status, not an NVML code; the conductor refuses it as a gate failure.

Host tools retained for verification: pinned omc and bridge; GCC for the C ABI ORACLE; sha256sum for pins; env and the existing bridge shell wrapper for invoking that pinned dependency. The gate itself implements composition, mutation, matching, pin parsing, child-status checks and summary generation in Omega. The one-time Make bootstrap uses cat/chmod/mv/mkdir as existing repository recipes do. Exact versions and evidence are in `evidence/NVML-2026-11-07/seeded/`. Scratch output is under `build/nvml/`; run one NVML gate at a time per worktree.
