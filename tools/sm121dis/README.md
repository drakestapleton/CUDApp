# sm121dis: Omega's own GB10 disassembler

A disassembler turns the GPU's machine code back into readable instructions. Omega used to borrow NVIDIA's
`nvdisasm` for that, in every check that reads a kernel back. `sm121dis` is my own (row C6 of `docs/OMEGA.md`):
the decoder is seeded Omega, `om/disasm/sm121_dis.om`, lowered by the pinned omega-bridge into
`src/cudapp_om_sm121_dis.c` (`om/units.sh`, byte for byte); `src/omega_sm121_disasm.c` only moves the bytes and copies
the text. The hand-written C decoder that came first stays in that file behind `CUDAPP_MIGRATION_PENDING_C_DISASM`, as
the differential oracle (`make CUDAPP_DISASM=om|c|diff`; CUDA++ C6, DRA-475). This folder holds the command line and
the comparison with NVIDIA's tool.

## What it proves

- Every kernel the library builds without the chip (each GPU test in its host-only and simulator modes, and every
  kernel the hazard checker's sweep builds) is collected and compared word by word with `nvdisasm`, text and spacing
  included. On 2026-11-07 (CUDA++ C6, DRA-475, host, Omega decoder): all 3,191 kernels (1,237,248 instruction words)
  agree, 0 differ (`evidence/C6-DISASM-OM/`). `corpus.sh` writes `MANIFEST.tsv` (every kernel's SHA-256, size, words
  and first producer; that day's manifest has SHA-256 `0939127a973c165f163694a3fa4b4cb3ae398d9e80b8d8560c427eb073e2c4ce`)
  and `PRODUCERS.tsv` (new kernels per producer run: 789 from the GPU tests, 2,402 from the hazard sweep).
- Older counts: 331 kernels (59,152 words) on 2026-10-24 and 402 kernels (74,096 words) on 2026-10-25 are the receipts
  in `evidence/C6-DISASM/`, from before the hazard sweep joined the corpus; 2,980 kernels (1,218,992 words) on
  2026-10-30 is the first count with the sweep (7919aada). The 3,191 of 2026-11-07 is the same corpus after later
  producers and generators (gpu_mathlibs_test, 36 kernels, joined on 2026-11-04 in 679fd24f); it equals the encoder
  corpus count of `evidence/ldg-offset-20261107`.
- A copy of the decoder with one planted fault (the C oracle with `SM121DIS_MUTANT`, first source register off by one
  bit) must fail that comparison with a verdict. Three one-line mutants of the `.om` decoder, each regenerated by the
  pinned compiler and bridge, must each change the corpus text (`make test-sm121dis-om-mutants`).
- The `.om` decoder and the C oracle are run on every word of the corpus (the `CUDAPP_DISASM=diff` build aborts on any
  difference in status, text or EXIT flag); the same build with one bit flipped on the C side must abort.
- Flipped-bit control (`negctl.sh`): flipping bit 16 of word 0 in each kernel must change our text and break parity in
  exactly that word.
- A kernel that could not be saved whole (a full disk) fails the collection; it is never compared cut short.
- A word the decoder does not know is printed as `?? <hex>` and fails the check. It is never guessed. That includes a
  special register nvdisasm names but this decoder does not (96 of 256 values; an S2R sweep, `sr-sweep.sh`).
- BlackwellIR ops 64..79, the numbers the #280 integration moved (ATOMG.E.MIN.64 stays at 64; its conversions and
  binary64 forms are 65..79, `evidence/INTEG-280-20261110/numbering.txt`): `make test-sm121dis-opmove` encodes one row
  of each with the seeded encoder (`om/disasm/opmove_test.om`), and my decoder must know every word with the op's
  mnemonic while nvdisasm 13.0.85 prints the same text. The rows numbered as before the move must fail. Before the
  2026-11-10 rows were added, 14 of those 16 words printed `??`; the C oracle got the same rows, so `diff` still
  agrees.

## How to run it

    make test-sm121dis          # collect, compare with nvdisasm, then the red check

`nvdisasm` is used only here, as the reference to compare against. Nothing it prints goes into a kernel.

## Who uses it

The checks that used to call `nvdisasm` now call mine:

- the listing checks inside `tests/gpu_elementwise_test.c`, `gpu_fp8_api_test.c`, `gpu_reconv_test.c`,
  `gpu_attention_test.c` and `bench/prime_race/tests/gb10_sieve_host_test.c` (linked in, `omega_sm121_listing`);
- `tools/divsqrt_nvdisasm_check.sh`, `tools/ldst_nvdisasm_check.sh` and `make test-numeric-reduce-nvdisasm`
  (the `build/sm121dis` command);
- the hazard checker's register cross-check, `tests/bw_hazard_test.c --disasm` (`make test-bw-hazard-nvdisasm`,
  linked in, `omega_sm121_disasm`), over every kernel its sweep builds. Those kernels are in the comparison corpus.
- `tests/device-trace/run-emitter-checks.sh` (`make test-device-trace-emitter`, with its red decoder; the device-side
  trace emitter's 40 words; nvdisasm only when `NVDISASM` is set, as an oracle that must print the same text) and
  `tools/artifact_smoke.sh` (each artifact's kernel text).
  Every remaining nvdisasm call site, with its class, is in `evidence/C6-DISASM-OM/NVDISASM-CALL-SITES.md`.

The script and target names are kept so older receipts still line up. `make test-zero-nvdisasm` proves that none
of these checks runs `nvdisasm`.

## Files

| File | Job |
|---|---|
| `sm121dis.c` | command line: a listing, `-b SM121` (called like nvdisasm), `--pairs` (for the comparison), `--version` |
| `corpus.sh` | runs every GPU test with `OMEGA_KERNEL_DUMP_DIR` set, so each kernel the library encodes is saved |
| `check.sh` | compares my text with nvdisasm's for every saved kernel, `SM121DIS_JOBS` at a time (default: every CPU the process may use); PASS only when every word agrees |
| `oracle_pairs.sh` | turns nvdisasm's listing into the same one-line-per-word form |
| `negctl.sh` | ORACLE harness: the flipped-bit negative control of the comparison |
| `om_mutants.sh` | three `.om` decoder mutants through the pinned compiler and bridge; each must change the corpus text |
| `oracle-allow.tsv` | the declared oracle lines the ZERO-NVDISASM static check accepts, each with its reason |

## Exact MMIO semantic contract (issue #171)

`BW_IR_LDG_MMIO` promises `LDG.E.MMIO.GPU`, not the historical encoder's EF
cache policy. `make test-sm121-mmio OMEGA_MV=/path/to/pinned/omega` concatenates
the production encoder with `om/encoder/mmio_test.om`. The Omega fixture emits
one instruction and checks NVIDIA nvdisasm 13.0.85's exact mnemonic and register,
descriptor and address operands. It then emits an otherwise identical EF
mutant; the same Omega expectation must refuse it with exit status 4.
The seeded compiler SHA-256 remains pinned; the oracle's version and binary
SHA-256 are recorded. Neither decoder output nor mutant bytes enter production.

This tests an IR semantic promise, unlike a decoder-only comparison that can
agree about the wrong instruction. Existing golden receipts are not rewritten.
Before/after corpus identities record any emitted-kernel byte impact separately.
GB10 cache behavior and device execution remain **NOT_RUN**; no live model is
rebuilt, replaced, or deployed by this check.

The recorded pre/post comparison at base `e84326dca9f1ef9afbeaf249fb3e46ae0a2517f7`
has **773 identical existing SASS kernels and four identical captured cubins**
(including a copied bundle used for manifest-tampering controls).
The complete before/after SHA-256 maps and empty changed-kernel/artifact lists
are in `evidence/CUDAPP-SM121-MMIO/corpus-impact.json`, bound to exact source,
generated binding and NVIDIA oracle identities. The existing producer corpus
does not exercise op21; the new single-op fixture does. The generated encoder
and host library bytes change as expected, but no deployed artifact is rebuilt
or loaded. Corpus equality is not cache-behavior or device qualification.

The final canonical replay uses baseline
`c6977b4906229fe83f41103b7eff65b64a0986d6` and corrected implementation
